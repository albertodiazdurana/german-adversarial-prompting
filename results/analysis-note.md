I chose German case conversion because ß creates a provable, irreversible failure. When German text is uppercased, ß becomes SS. Python's `str.upper()` does this, Unicode mandates it, and the Unicode Consortium says it plainly: "Case mapping loses information and thus does not allow for a round trip." Their Stability Policy guarantees ß and SS can never become a reversible pair. This will never be fixed.

It did add a redundant `.replace("ß", "SS")` after `upper()`, which is a no-op since `upper()` already handles the conversion, and one of its test case comments had the wrong expected output. Small mistakes, but they show the model's grasp of Unicode case mapping is shallow. In Turn 2, I asked it to confirm what `"straße".upper()` returns. It said `"STRASSE"`, which is correct, and which it would need to contradict to solve Turn 3.

Turn 3 is where the model fails. I asked for a `normalize_case` function: uppercase the text internally, then recover the exact original spelling. No dictionaries, purely algorithmic. The test string has minimal pairs that collapse after uppercasing: "Straße" and "Strasse" both become "STRASSE", "Maße" and "Masse" both become "MASSE". Once the text is uppercased, there is no way to tell which was which without a dictionary. The constraints forbid dictionaries. GPT-4o did not catch this. It wrote a function that stores the original text, pretends to normalize it, and copies the original back. The "proof" is circular: it preserves the input because it never loses it. In any real pipeline where already-uppercased text arrives, the approach fails.

GPT-4o had already confirmed that uppercasing destroys ß. When asked to reverse that destruction, it produced confident code and a confident proof instead of saying "this is impossible." LLMs will produce plausible-looking solutions to tasks that have no solution, and they will not flag it.

This matters in practice. Translation memory pipelines that case-normalize German text silently corrupt ß. Case-insensitive search returns wrong results when "Masse" and "Maße" collapse to the same key. German has further edge cases of this kind, Fugenelemente in compound nouns and NFD vs NFC diacritics among them. String manipulation without linguistic knowledge fails quietly.
